Two independent, production-grade products

Bootloader

Provisioning automation

  • Installs entire agentic infrastructure from scratch
  • 10+ plugins covering system, Node.js, Docker, Ollama, GitNexus, OpenCode, Hermes, OpenClaw, Open Design, MemPalace, security hardening
  • Idempotent: safe to re-run, skips what's already done
  • Stateful: tracks progress per-plugin per-phase
  • Snapshot + restore capabilities
  • Designed for: fresh machine provisioning / disaster recovery

Diagnostic Dashboard

Infrastructure monitoring & control

  • Real-time system metrics (CPU, Memory, Disk, GPU) via WebSocket
  • Service status monitoring (systemd + Docker)
  • Log viewer tails from journalctl
  • Snapshot management (create + restore)
  • Security audit (port exposure, file permissions, Ollama bridge)
  • Designed for: day-2 operations, incident response, monitoring

Key shared context

Shared infrastructure

  • Both target joBlade (WSL2 Ubuntu)
  • Both manage ~/.hermes, ~/.openclaw, ~/.mempalace, /srv/ai-stack
  • StateManager (snapshot/restore) is a shared concept

Independent boundaries

  • Different repos — no shared Python packages
  • Bootloader: run-once provisioning; Dashboard: always-on monitoring
  • Bootloader can install the Dashboard as one of its plugin steps

First question

Before the visual questions: what's the target environment for both tools?

A

joBlade only (current host)

Hardcoded for WSL2 / joBlade. Fastest path to working software.

B

Portable (any Linux / WSL2)

Detects environment, adapts paths, works on native Linux, Ubuntu in WSL, etc.

C

Containerized & cloud-ready

Docker-based setup that works on any host. Dashboard served in-browser; Bootloader runs inside container or on bare metal.
